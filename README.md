# MoleculeTrace

**MoleculeTrace Learning System** — a 24-week, project-based Database Management
Systems course built around a molecular data and machine-learning experiment
registry.

MoleculeTrace models the chain:

```
molecules → biological targets → assays → activity observations
          → versioned datasets → ML experiments → model versions
          → predictions → validation
```

The goal is to teach a complete university DBMS syllabus while producing a
credible AI-engineering and molecular-ML portfolio project.

> **Educational use only.** All molecular results produced by this project are
> teaching artefacts. They are not scientific findings, not medical advice and
> must not be used for any clinical or drug-development decision. Any data
> generated by the project's own scripts is explicitly labelled *synthetic*.

## Who this is for

A student who already knows basic Python and Git, introductory DBMS concepts,
basic ER modelling and relational design, basic SQL, and the theory of an ML
pipeline — but who has limited experience wiring a database, a backend and an ML
workflow together. Budget: **about five hours per week for twenty-four weeks**.

## Scope rule

**Keep the molecular ML simple and explore the database deeply.**

Explicitly out of scope: molecular docking, protein-structure prediction, graph
neural networks, molecular generation, clinical information, drug
recommendations, and complex cloud infrastructure.

## Technology stack

PostgreSQL · Python · FastAPI · psycopg · Pydantic · Streamlit · pandas ·
scikit-learn · RDKit · pytest · Docker Compose · GitHub

## Repository layout

| Path | Purpose |
|------|---------|
| `curriculum/week-XX-*/` | The lessons. Everything you actually do lives here. |
| `curriculum/_TEMPLATE/` | The standard week template used to create each week. |
| `project/database/` | Schema, migrations, seeds and saved queries. |
| `project/backend/` | FastAPI service and Pydantic models. |
| `project/frontend/` | Streamlit dashboard. |
| `project/ml/` | Feature building, training and evaluation with scikit-learn and RDKit. |
| `project/data/` | Raw, processed and clearly labelled synthetic data. |
| `project/tests/` | pytest suites for the project code. |
| `labs/` | **Pointers only.** One short markdown file per cross-cutting topic linking to the week that teaches it. |
| `docs/` | Design documents, decision records and diagrams. |
| `scripts/` | Small helper scripts invoked by the `Makefile`. |
| `instructor/` | Rubrics, validation notes and solution notes. Read *after* attempting the work. |

### The `labs/` rule

`labs/` contains **only** short markdown pointer files. No starter code, no
exercises, no tests, no expected outputs. If the same content appears in both
places, `curriculum/week-XX/` wins and the `labs/` file must be corrected to
point there.

## Getting started

```bash
cp .env.example .env      # then edit the values
make up                   # start PostgreSQL via Docker Compose
make psql                 # open a psql shell inside the container
```

Then open `curriculum/week-00-orientation/README.md` and follow it.

Python environment:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```
